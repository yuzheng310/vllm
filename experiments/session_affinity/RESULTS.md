# 阶段结果与必要性判断

后续复核：以下 0.6B 数据和反证均保留。目标 4B 的 KV 容量约小一半，
不能用本卡片直接否决未测的 4B；已收窄为目标容量下的一项待验证问题，见
[两轮实验后的再选择](../rollout_audit/POST_EXPERIMENT_SELECTION.md)。

结论：值得做这次有边界的验证，但当前不值得继续作为主要简历成果投入。
原版只调活动轨迹并发就能追回大部分差距，尚未证明我们的实际系统必须
保持高会话并发。目标中的“有必要、收益显著”的二开成果尚未达成。

以下是 Qwen3-0.6B 的真实权重结果；未运行 4B，不能外推为 4B 或训练加速。
候选源于 PR 51384，本项目移植、收紧恢复边界并减少满载时的无效扫描。

## 未修改发布版的交替对照

基线：v0.29.0，`98dff2a81d747d1dba01a47f939f48c3526d4206`，worktree 干净。
候选：`af01b094eeee92c4ff061b166d556835a94717c0`。

均开启。48 条冻结公开代码定位轨迹、233 请求、16 并发、轮间模拟 0.25s。
候选队首让行阈值为 2s。顺序为 A1、B1、B2、A2，每次新建引擎并清空缓存。

整批墙钟下降约 11.0%，轨迹吞吐提升约 12.4%。两次重复不能代表所有硬件、

轨迹执行 P95 从该轨迹被客户端 worker 取出时计起，不含尚未启动的任务池
等待；原始数据另有从整批起点计的 completed_s，避免混淆两种尾延迟。

机制上，两侧缓存查询 token 总数都是 2,661,314。命中从 1,801,664 增至
1,984,032，每轮减少 182,368 个未命中 token。没有抢占，因此不能把收益
描述为减少抢占重算。更准确的是在并发队列中及时兑现尚在本地的历史缓存。

## 更强的原生配置对照

相同任务，原版把同时活动的轨迹数从 16 降到 8，耗时为 54.728s；
候选在 8 并发时为 55.266s。此处没有有意义的正收益，约 1% 差异不当作
稳定回归结论。它符合“排队/缓存竞争不足时，本策略不该被视为加速手段”。

这也削弱了必要性：相较原生 8 并发，候选 16 并发的墙钟优势只有约 2.2%。
不能把固定 16 并发下的 11% 宣传成相对原版最佳配置的峰值吞吐优势。
这里降低的是同时活动的完整 Agent 轨迹数，连带降低工具并发；它不同于
vLLM 原有 max_num_seqs=8 对单次模型请求的限制，后者两侧都已经开启。

如果真实系统可以降低活动轨迹数且工具等待很短，先调原生并发是更便宜的
选择。若需要保持较多并行工具会话，这项引擎策略才有更强理由。已有公开
轨迹不含工具耗时，不能编造一组长工具等待来证明我们项目必须高并发。
当前结果不够支撑“无需条件、值得直接作为项目主要简历收益”的判断。

## 初筛记录与副作用

- OMP=4 的初筛，30s 阈值使墙钟下降约 16%，但冷首轮 P95 从 8.69s
  增至 14.03s；默认 0.5s 只有约 5.7% 增益，冷首轮延迟改善。
  两组原始数据均保留，没有只挑最大的百分比。
- 后续用原生建议的 OMP=1 重跑双方，并根据基线排队中位数约 1.65s
  选择 2s，让行更保守。不能把不同 CPU 设置之间的差距归功于调度改动。
- 低并发两轨迹 eager 功能检查：缓存命中完全相同，8 个请求输出 hash
  全部一致，耗时相差不到 1%；这不是性能收益证明。
- 默认数值模式下，改变批次顺序会改变部分完整生成序列的 hash。初筛
  基线自身两次重复只在 158/233 个请求上完全一致；跨策略首轮是 96/233。
  不能据此宣称模型质量下降，也不能宣称输出逐 token 一致或无精度损失。
  确定性模式的补充对照用于进一步排除调度正确性问题，结果见下一段。

确定性补充对照已完成：VLLM_BATCH_INVARIANT=1 时，233/233 个请求的
完整输出 token hash 相同。这个受测范围内没有发现改变调度后计算结果
不正确的证据。原版/候选墙钟为 109.898 / 108.596s，只有约 1.2% 差异；
它证明的是该模式下受测输出一致，不能拿默认模式的 11% 与这里的逐 token
一致性拼成同一组“无损提速”成绩。此处仍用 2s 阈值，没有为扩大收益再调参。

全部结果是固定历史输入和固定生成长度的推理回放。后续轮次仍取历史输入，
不由本轮生成内容驱动真实工具。完成率表示回放请求执行完成，不能替代
Agent 定位正确率、reward、训练收敛或整个 RL 系统吞吐。

## 停止条件与资料

本次已检验作者机制、保守阈值、交替重复、原版调参及输出一致性边界。
不继续扫阈值、拉长模拟工具耗时或更换压力点来寻找更大的数字。
4B 本地完整权重已核对官方 SHA，但远程下载多次超时；最后一轮分段下载
在约 27 分钟时主动停止，第一 shard 已验证，第二 shard 最后进度日志
为 576/951 个 4MB 片段。保留片段以便有真实需求时复用；未占用 GPU 等待。
停止扩展的主要依据是必要性证据减弱，而非将网络故障当作性能结论。

后续重启需有实际场景证据，例如真实工具等待确实要求高会话并发，且
原生降低并发影响完成时间；再验证目标模型与真实工具闭环，而非直接
采用本回放的 11% 作为 RL 系统收益。本次不修改简历。

- `results/` 保留全部成功回放的逐请求、逐轨迹 JSON，包括低收益结果。
- `results/run-logs.tar.gz` 保存本次引擎、测试与下载日志，以及同步前
  的临时补丁；失败日志也保留。归档清单与 SHA 见 `results/MANIFEST.json`。
- `summarize.py BASELINE.json CANDIDATE.json` 检查配置可比性并计算单对
  或文件内多轮结果；ABBA 的 A1/B1、A2/B2 分别比较，不跨并发混算。
- 实现、先前源码快照、数据准备代码与工作日志均在同一分支，作者来源
  和本项目修正分开提交。没有向上游发重复 PR。
