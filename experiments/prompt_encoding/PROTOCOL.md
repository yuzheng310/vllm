# RepoCompass 多轮请求分词复用：开发前协议

2026-09-14。按用户最新范围，只补充 RepoCompass 内一条有实测收益的
vLLM 开发工作；不再要求它成为独立项目或使整个训练提速 10%。
本阶段不启动 GPU，不修改训练算法、采样、任务长度或工具等待。

## 选择与真实消费者

选择 Qwen/ChatML 多轮请求的历史消息分词复用。RepoCompass 的 OpenHands
每轮提交完整消息，通过 SkyRL 到 vLLM ChatCompletion；训练还消费精确
prompt / response IDs。现有轨迹载荷裁剪在 Conversation 结束后执行，
不能省掉服务器每轮重新分词。KV 缓存也发生在文本已经转成 token 之后。

固定发布版 v0.29.0 的 BaseRenderer._tokenize_prompt 调用 tokenizer(...)
完整处理 rendered prompt。拟在该实际调用边界加入可选的消息段缓存，
保留原生模板、预校验、后校验、截断、输出结构；缓存不可服务时回退原路径。
实际训练依赖仍固定 vLLM 0.11.0；本阶段不宣称已经完成生产依赖迁移。

## 先例与选择依据

- PR 45514：按特殊 token 分段、可选 LRU 缓存。借鉴明确分段边界；其当前
  head 只覆盖 tokenizer.encode，不能直接假定覆盖 v0.29.0 的 __call__。
- PR 47583：在 BaseRenderer 接入前缀增量编码。借鉴其接入位置和回退契约；
  暂不采用任意预分词边界的通用拼接，避免把局部检查当作任意 tokenizer 的证明。
- PR 51281：裁剪 DecodeStream 初始化历史。作者有 CPU/TTFT 数据，但
  维护者指出任意 token 边界的文本安全风险，因此本轮降为次选。
- PR 55771：ChatCompletion 接受预先分词的输入。原生已有 KV 参数别名，
  而本项目并非已经在路由层分过词，不将搬动分词位置当作消除重复工作。

这些提案当前未合并。借鉴保留来源，不将他人指标写入我们的简历，
不新开重复上游 PR。项目不新增独立模型评测业务或多 LoRA 服务。

## 第一性原理与正确性约束

选取注册的 <|im_end|>，只在明确的特殊 token 边界切分 rendered text。
固定 CodeScout tokenizer 将它标为 special、normalized=false，且无
single_word/lstrip/rstrip。该标记在普通文本归一化与 BPE 之前被识别，
两边分别分词；拼接时保留原标记的 ID 和所有空段，不裁剪空白。

注意目标 tokenizer 存在 NFC normalizer，不能假设没有归一化。
注册特殊边界是所需条件；任意字符串分隔符或固定字符窗口不能替代它。
实现前需进一步核对 tokenizer 提取顺序与边界条件；当前结构推导不是
对所有模型的通用证明。任何不支持的模板/tokenizer/参数必须回退。

若整轮由旧段 H 与新增段 D 构成，原路径反复执行 Encode(H+D)，新路径
只编码缓存未命中的段，并重新构造完整 IDs。不可省去扫描、查表和 ID
拼接，也不减少 GPU decode 或实际工具执行。因此可复用的字符/token
比例只说明工作量结构，不等于分词耗时或端到端提速比例。

## 有边界的验证顺序

1. 仅数据审计：使用已冻结 48 条公开代码定位轨迹、233 请求，从原始消息
   按相同模板恢复文本。完整分词必须逐 token 匹配此前冻结的输入；再验证
   在特殊边界分段拼接与完整分词一致。统计包含冷首轮的重复字符与 token，
   不改选任务，不用字符串填充，也不做性能扫描。
2. 审计通过后实现有限范围的 vLLM 前端扩展。共享缓存受条目数与存储预算
   双重约束，按 tokenizer 实例和 cache_salt 隔离；保证调用方不能修改缓存
   中的 ID 序列。线程池并发、淘汰、错误参数、模板/词表变化均须有明确行为。
3. CPU A/B 使用相同真实 rendered prompts，覆盖冷首轮、后续轮、交错会话；
   计入拆分、缓存查找、拼接和回退。对照原生 __call__、无缓存分段和已有
   可用后端优化（特别是 fastokens），不只比单线程旧实现。
4. 主要指标是该批请求的总分词耗时、每请求 P50/P95、CPU 成本和缓存容量。
   暂定分词阶段累计耗时下降至少 30% 才值得保留，任何 token 差异停止。
   这是局部投入门槛，不是预告成绩。短请求/冷路径回归须单列。
5. 局部收益成立后才做最小真实服务接入，确认在线请求确实走到扩展且完整
   token IDs、工具调用内容一致。服务请求完成时间与前端分词耗时分开报告，
   不将 CPU 模块加速写成 RL 吞吐提升，不复现完整多卡训练。
