## E002：nvidia-smi 失败并不只是监控问题

- 现象：`Failed to initialize NVML: Driver/library version mismatch`。
- 内核模块版本为 `580.173.02`；系统 NVML 和 libcuda 为 `580.178.04`。
- 标准库 ctypes 调用 `cuInit(0)` 返回
  `804 CUDA_ERROR_COMPAT_NOT_SUPPORTED_ON_DEVICE`。
- `/proc/self/maps` 证明实际加载的是较新的系统 libcuda，
  `LD_LIBRARY_PATH` 和 `LD_PRELOAD` 均未设置。
- 判断：GPU 计算入口也失败，不能通过安装 PyTorch 来掩盖此问题。

## E003：目录内修复，不升级共享系统

- 系统里没有可直接选择的 `580.173.02` 用户态库。
- 从 NVIDIA 官方 Ubuntu 22.04 仓库下载同版本 compute/gpucomp/utils 包，
  按 HTTPS Packages.gz 的 SHA256 字段验证，使用 `dpkg-deb --extract`
  解到工作目录，而非安装软件包或运行维护脚本。
- 只给实验子进程设置匹配的 `LD_LIBRARY_PATH`。
  没有使用 sudo、重启、卸载内核模块、修改系统软链接或停止其他进程。
- 验证：NVML 恢复；显存总计 24564 MiB，观测到空闲 23782 MiB；
  CUDA 初始化返回成功，映射路径指向工作区内 libcuda。
- 再验证实际计算：分配 4096 字节、PTX JIT、启动 kernel、同步、拷回，
  1024 个整数结果全部吻合。清除继承的库路径后用启动脚本重测也通过。
- 限制：这只打通了 CUDA，不代表已经验证 PyTorch、vLLM 或模型性能。
  启动脚本检查内核版本，系统升级后应重新验证该覆盖。

## D001：选范围时区分功能价值与性能证据

- ZipServ 的公开集成不完整，小矩阵与频繁权重更新有风险；
  Seer/DAS 的新增收益还依赖本项目未观测的同题轨迹相关性。
- 本项目选择调用者已有的动作位置信息，直接删除不需要的 LM-head 行。
- 不做新的训练流程来制造优化需求，定位为轨迹打分能力扩展。
- 投影行可省约 97% 的长度推导不意味着端到端同等收益；
  4B 模型静态线性层 FLOPs 推导约省 7.5%，没有提前承诺提速数字。

## D002：首版保留原输出索引，控制跨模块工程量

- 原候选包含逐位置候选集合和紧凑新协议，工程涉及更多输出通路。
- 首版只增加 `prompt_logprob_positions`，输出保留完整 prompt 索引和空槽。
- 好处：现有调用端按原始位置取分数，EngineCore 无需新增位置协议，
  正常请求可保留原来的执行路径。
- 代价：最终输出仍包含 O(L) 空槽；必须测真实序列化字节，
  不能沿用之前紧凑协议的总字节缩减预测。
- 非连续位置的 UTF-8 解码应使用真实相邻输入 Token，
  不能把前一个被选择动作当作紧邻上下文。

## E006：macOS 归档元数据触发 Linux Git 报错

- `tar` 提示未知的 `LIBARCHIVE.xattr.com.apple.provenance` 扩展头；
  随后 Git 报 `._pack-....idx is too small`。
- 原因是复制 `.git` 时附带了 AppleDouble `._` 元数据，
  Linux Git 把其中的 `.idx` 后缀文件当成对象包索引。
- 仅删除这次归档生成的 `.git` 内 58 个 `._*` 文件及根部 `._.git`。
  清理后 `git status --short` 为空，提交 SHA 正确。
- 后续跨平台归档应关闭 macOS metadata/xattrs；
  不把这类归档问题误诊为需要重新创建 Git 历史。

## D005：在观测结果前调整 4B 测量方式

- 此决策发生于模型实验开始前，没有看过任何正负性能结果。
- 4B 权重约 8 GB，当前网络会让下载占据很长时间。
  先终止本项目的 4B 下载进程，保留已校验长度的 768 MiB 完整分段以便续传，
  让依赖与 0.6B 正确性验收优先使用网络。
- 本地源码 `DummyModelLoader` 和 `initialize_dummy_weights` 已提供原生随机权重
  性能测量路径；使用固定的每参数随机种子和小范围随机浮点权重。
- 对本实验的稠密 Qwen3、固定输入长度、固定生成一步、关闭推测解码、
  `prompt_logprobs=0` 和禁用文本解码，算子形状与循环次数由结构决定。
  概率内核仍扫描完整词表，没有因分数值提前退出的路径。
- 因此可用真实 4B 结构与随机权重测执行成本，省去预训练权重传输。
  这不是 CPU 模拟器，仍执行真实 Transformer、LM head、概率内核和结果通路。
- 但不能据此保证运行时间与真实权重逐项相同。先对照 0.6B 的真实与随机权重，
  定量检查代理偏差；4B 结果明确标注随机权重，不作模型质量或真实权重成绩。
- 协议相应更新：真实权重结果以 0.6B 为准，4B 作为结构成本证据。
  两类结果分开报告，不选取更好的一组冒充同一个实验。
