# 实验协议：先定义可证伪的问题

## 目标与范围

让多轮 Agent 的轨迹打分只为指定动作位置执行词表投影，
在单 GPU 上验证概率语义与实际成本。第一版限定原生 Python API、
V2 CUDA runner、decoder-only 文本输入，不做训练、量化、分布式或新 CUDA kernel。

一次仅验证一个假设：

| 假设 | 证据 | 失败意味着什么 |
| --- | --- | --- |
| 指定位置确实在 LM head 前被筛选 | 投影行计数与跨块测试 | 只是接口过滤，没有省模型计算 |
| 目标位置与原分数一致 | 同位置分数、偏移反例、误差分布 | 因果偏移、归一化或分块错误 |
| 分块/混合请求/抢占不破坏结果 | 边界和生命周期回归测试 | 引擎实现不完整 |
| 少做工作能减少完整请求耗时 | 交替对照与原始计时 | 局部节省未转化为目标收益 |

## 请求与结果契约

`SamplingParams.prompt_logprob_positions` 接收递增、唯一、非空的目标 Token
位置列表；位置 j 对应 hidden-state 行 j−1，范围为 `1 <= j < prompt_len`。
必须同时设置 `prompt_logprobs`，沿用其目标 Token/Top-K 概率语义。

输出仍为 `RequestOutput.prompt_logprobs`，索引与完整输入一致。
未选择位置为 None，FlatLogprobs 使用现有空槽表示。
这是对原接口的向后兼容扩展，不是严格 O(AK) 的紧凑输出协议：
最终结果仍有 O(L) 位置占位；完整序列化字节必须包含这些占位。

概率必须在完整词表上归一化。工具 Token 的 Transformer 计算必须保留。
不支持的配置应当拒绝，不能静默返回全量分数冒充稀疏模式。

## 固定基线与数据

- 代码：v0.29.0，`98dff2a81d747d1dba01a47f939f48c3526d4206`。
- 真实权重正确性与性能：Qwen3-0.6B BF16。
- 4B 结构成本：Qwen3-4B 配置、原生 DummyModelLoader 随机权重、BF16。
  先在 0.6B 的同一结构上对照真实/随机权重，校验这个成本代理的适用程度。
  4B 随机权重成绩必须单独标注；不当作真实 4B 权重的性能或质量结论。
- 下载时记录模型 revision、包版本和硬件状态。
- 主范围：4K/8K/16K Token、batch=1、约 3% 动作位置、多个动作区间。
- 首轮为公开说明构造方法的合成代码/工具轨迹，保存 Token IDs 与 mask。
  参考公开轨迹只有长度，不声称已经获得真实 RepoCompass 训练 Token trace。

对照包含未修改原版、修改后未启用功能、连续后缀选择、非连续动作选择，
以及逐轮仅打分动作后缀的可行替代方案。连续后缀的同实现控制是消融，
不是对上游 #54335 的独立复现。不能只与全词表输出比较。

主配置 `prompt_logprobs=0` 已返回实际目标 Token 的分数。
额外 Top-K 只作补充，不通过选择大 K 放大主结果。

## 正确性门槛

测试应覆盖位置 j−1、块首/块尾、没有动作的分块、最终块没有动作、
批内不同 mask、请求清理、抢占重算、DELTA 一次性交付及 UTF-8 上下文。
纯位置/结果恢复先用便宜的单元测试，GPU 只验证必须依赖真实执行的部分。

不同 GEMM 形状或不同 forward 的 BF16 结果未必逐位相同。
同一 forward 的概率参照与跨形状的数值差异分开记录，
结合原版分块变化的数值波动判断，不能只放宽阈值让测试通过。

## 性能测量

- 相同 dtype、runner、attention backend、缓存、调度预算和输出格式。
- 预热后交替执行对照，至少 10 轮配对测量，保存每轮原始值，
  报告中位数和分位数。共享 GPU 明显繁忙时暂停，不停止其他任务。
- 投影计数/profiler 与正式计时分离，避免测量工具污染性能结果。
- 同时记录投影行、结果元素、完整序列化字节、显存和完整请求时间。
  必需的尾部生成与位置参数处理也计入成本。

约 97% 的投影行减少不等于约 97% 的请求时间减少。
根据本模型线性层 FLOPs 的静态推导，参考长度几何对应约 7.5% 的线性层
计算量节省；Attention、归一化、CPU 输出与矩阵效率会改变实际耗时。
因此不提前承诺整体提速比例。

正确性失败先修复；性能无收益时保留结果，不通过换任务或扩大工程范围
制造成功。训练 F1、收敛与多卡扩展均不属于本次结果。
